## [0.24.2] — 2026-08-02

Выбор монитора ломал сам себя: «Монитор 'HDMI-A-1 (1920x1080)' не найден.
Доступны: eDP-1, HDMI-A-1». В `output` уходил ярлык из списка, а захвату нужно
имя — стереть « (1920x1080)» руками действительно помогало.

- Причина: при пересборке списка мониторов (кнопка обновления, повторное
  применение настроек) запоминался текст поля, а не имя монитора. Поле
  редактируемое, поэтому текст возвращался в него как есть, выбранный пункт
  «терялся» — и в конфиг сохранялся ярлык целиком.
- Значение списка теперь всегда берётся из данных пункта, а не из подписи;
  вписанное руками имя по-прежнему сохраняется как есть.
- Уже испорченный конфиг чинится сам: ярлык распознаётся и при загрузке в
  интерфейс, и в самом захвате — правка `config.json` руками не нужна, в том
  числе для `--live` без GUI.

## [0.24.1] — 2026-08-02

Захват на Wayland не работал в собранном бинарнике: «Не удалось получить список
мониторов через hyprctl … returned non-zero exit status 1». Из исходников всё
запускалось, поэтому ошибку не было видно при разработке.

- Причина: PyInstaller подставляет в `LD_LIBRARY_PATH` свою временную папку с
  библиотеками сборочной машины (Ubuntu), и её наследуют дочерние процессы —
  `hyprctl`, `grim`, `wf-recorder` грузили чужой `libstdc++` и падали ещё до
  работы («version GLIBCXX_3.4.35 not found»). На дистрибутивах со свежим
  toolchain (Arch и др.) захват не запускался вообще.
- Сторонние программы теперь запускаются через `adalight.subproc` — с
  окружением, каким оно было до старта бандла (`hyprctl`, `grim`, `wf-recorder`,
  `pkexec` для udev-правила, `dbus-monitor` для вспышек уведомлений).
- Ошибки стали объяснимыми: в сообщение попадает вывод самой утилиты — было
  «returned non-zero exit status 1», стало «hyprctl monitors: код 1, hyprctl:
  … version GLIBCXX_3.4.35 not found». То же для `wf-recorder`: его stderr
  больше не уходит в никуда, а показывается в причине падения.
- Вёрстка: длинные пункты списков («Спектр по периметру», путь к порту, имя
  монитора) распирали колонку настроек шире её максимума, и правый край формы
  уезжал под предпросмотр — на многомониторных системах кнопка обновления
  списка мониторов становилась недоступной.
- Пояснение к расписанию яркости переехало из подписи галочки в подсказку, имя
  плагина в менеджере обрезается многоточием вместо полосы прокрутки.
- Скриншоты в README обновлены: английские для `README.md`, русские для
  `README.ru.md`.

## [0.24.0] — 2026-07-25

Производительность вывода и работа с портом. Приложение отдавало на ленту
~25 кадров в секунду при свободном канале на 137; профилирование показало, что
почти всё время кадра съедало усреднение зон по полному кадру, а потолок цикла
задавал `target_fps: 30`.

- Усреднение зон переведено на фиксированную сетку отсчётов (16×16 на зону,
  один векторный вызов numpy на кадр): было ~35 мс на кадре 1080p, стало
  ~1.5 мс — время больше не зависит от разрешения экрана.
- `target_fps` по умолчанию поднят с 30 до 120: потолок теперь задают захват и
  скорость порта, а не таймер приложения. В сохранённом конфиге старое значение
  остаётся — поднимите «Целевой FPS» в настройках.
- Тесты «стороны» и «бегущая точка» шлют кадры на полной скорости тракта и
  показывают fps — это встроенный замер пропускной способности без внешних
  скриптов (точка по-прежнему движется в глазном темпе).
- Счётчик реального fps (усреднение за секунду) во всех режимах, в
  статус-карточке и в подсказке иконки трея.
- Предпросмотр обновляется не чаще своего fps (по умолчанию 15, настраивается
  во «Внешнем виде») — перерисовка интерфейса больше не мешает циклу вывода.
- Встроенный профилировщик конвейера: `ADALIGHT_PROFILE=1` печатает раскладку
  кадра по участкам (захват / кадр / порт / предпросмотр / ожидание) в stderr.
- Отключение платы на ходу больше не роняет подсветку: движок переходит в
  «Ожидание платы…», переоткрывает порт каждые 2 секунды и сам продолжает
  работу после переподключения (события `device.lost` / `device.restored` —
  и для плагинов).
- На Linux порт запоминается стабильным путём `/dev/serial/by-id/…`, который
  привязан к чипу и переживает смену номера (`ttyUSB0` → `ttyUSB1`). Если порт
  всё же исчез, а среди портов ровно одна плата — открывается она.
- Чипы различаются по паре VID:PID (CH340 и CH9102 больше не путаются);
  порты с неизвестным чипом не прячутся, а показываются группой «другие порты».
- Сборка релиза теперь проверяется запуском: собранный бинарник обязан
  стартовать (на Linux — ещё и поднять окно), иначе релиз не публикуется.
  Прежняя проверка убеждалась лишь в том, что файл существует.
- Ошибка прав доступа (`errno 13`) больше не выглядит как «плата не найдена»:
  отдельное окно объясняет, что устройство видно, и предлагает установить
  udev-правило одной кнопкой (через pkexec) или показать команду для ручной
  установки. Правило (`packaging/99-adalight.rules`, `TAG+="uaccess"` — права
  через systemd-logind, без групп и перелогина) входит в поставку и в релиз.

## [0.23.0] — 2026-07-21

- Исправлено: на Windows встроенные моды (эффекты лампы, цветомузыка, захват
  экрана, транспорты) не находились — приложение сообщало «не удалось найти
  плагин» и по сути не работало. Причина — динамическая загрузка модов по
  строковому имени, которую сборщик `.exe` (PyInstaller) не видел и не
  упаковывал в дистрибутив. Теперь моды подключаются статическими импортами и
  всегда попадают в сборку. На Linux ошибка не проявлялась (запуск из
  исходников).

- Тело GitHub-релиза теперь подробное: «что нового», описание и возможности,

## [0.21.0] — 2026-07-19

- Починка CI: в раннер доставляются системные библиотеки Qt (тесты, трогающие
  интерфейс, снова выполняются на CI).
